# Dynamic House 受控重跑：R（记忆表示）× P（策略提示）

> 模型 `minimax-code-global/MiniMax-M3.1-Flash` · 1800 局（100 个种子 × 3 个 p × 6 个臂）·
> 32,841 次调用 · 2026-11-17/18 · 预注册见 [`PREREG.md`](../PREREG.md)（`git tag prereg-v1`），
> 全部表与图由 `uv run python -m dynhouse.analyze` 从真实日志重建。

## 1. TL;DR

1. **对照设计修好了**：阴性对照 S0 = **+0.5pp，95% CI [+0.0, +1.5]**（0 在区间内，下界恰为 +0.0）。pilot-v1 在 p=0 那个
   约 10pp 的差距正是「臂混杂」的指纹，现在它消失了 —— p=0 时 ledger 臂与 append 臂几乎逐局一致。
2. **记忆结构无效**：S（ledger − append，同提示）= **+2.3pp，CI [−3.2, +7.5]** → `STRUCTURE_NOT_NEEDED`
   （CI 上界 7.5 < δ=10pp，是「确知小于门槛」而非「分不清」）。
3. **轻量策略提示无效**：Π（cost − neutral，同记忆表示）= **+1.8pp，CI [−4.0, +7.5]** → `PROMPT_NOT_NEEDED`。
4. 预注册内唯一一次 N=100 延伸（种子 1060–1099）跑完后结论不变 → **决策表第三行：负结果叙事**
   （受控实证 + 失败分类）。
5. **记忆本身有价值，但只在世界静止时**：p=0 时 app/led 比 win 高 **+49～+50pp**（CI [+39, +59]，不含 0）；
   p=0.2 / 0.4 时六个臂彼此**分不开** —— 有记忆和没记忆一样。
6. **瓶颈不在记忆结构、也不在提示，而在「证据立刻过期」**：用观察到的证据抓取，抓空率
   p=0.2 **17.6%**、p=0.4 **31.3%**；而用**人的答案**抓取，抓空率 **0.0%**（1342 次抓取无一落空，
   因为环境规定被问过的物品在抓住前不再被移动）。
7. **失败分类**（696 局）：问人浪费 313、核验后目标又被移走 204、信了过期记忆 178、格式无效 1。
8. **93.7% 的失败局在用掉唯一一次问人后又问了一次**（被环境判 `INVALID: ask limit reached.`），
   **77.3%** 因此耗尽预算 —— 问人上限对 agent 不可见（公共状态里没有「还能问几次」）。
9. **LLM 臂与 20 行脚本基本打平**：p=0.2 最好 67.0%（led_C）vs 脚本最好 64.0%（ledger_gate）；
   p=0.4 最好 48.0%（app_N）vs 脚本最好 44.0%（ask_fetch）；p=0 时脚本全 100%，LLM 记忆臂 99–100%。
10. **成本**：p=0.2 时 `app_N` / `app_C` / `led_C` 相对 `win_C` 记为**「成本占优」**（成功率不低于对照，
    cost 配对差 CI 上界 < 0）；其余组合没有。

## 2. 与 pilot-v1 的差异

pilot-v1（`gnk48lb/gate_dynamic_house`，1440 局）不是「记忆结构有效」的证据，而是**对照设计不成立**
的产物。本实验针对 pilot-v1 的四条缺陷逐条修复：

| pilot-v1 的问题 | 本实验的修复 | 怎么验证的 |
|---|---|---|
| **臂混杂**：ledger 臂多拿约 6,000 字符环境专用策略提示（系统提示 7,388 字符），append-only 臂只有 1,342 字符基础提示 + 一句话；p=0（世界静止）时仍差约 10pp | 六臂共用**逐字相同**的 `BASE_SYSTEM`（2,502 字符），P=C 只追加固定 441 字符 | 阴性对照 **S0 = +0.5pp，95% CI [+0.0, +1.5]**：p=0 时两个记忆臂几乎逐局一致。pilot-v1 在 p=0 的 10pp 差距正是臂混杂的指纹，现在它消失了 |
| **环境偏向「总是问人」**：不依赖巡检记忆的脚本 `ask_fetch` 成功率 94–100% | 环境加 `max_asks=1`（每局只能问一次），并把 `ask_human` 改成整词匹配 | 旧环境原样：`ask_fetch` = 100 / 96.1 / 94.2；新环境主版本（1000 个种子）：`ask_fetch` = 100 / 66.3 / 46.3。**没有任何脚本策略一招通吃** |
| **`ask_human` 子串匹配**：`book` 命中 `notebook`，60 个种子里有 11 个的目标永远问不了人 | `named_items(question)` 整词匹配，下划线与空格等价 | 单测：18 个物品名逐个可问；`notebook` 不命中 `book`；`coffee mug` = `coffee_mug` |
| **双模型设计不可复现**（DeepSeek 额度耗尽） | 只用无限额度的 `minimax-code-global/MiniMax-M3.1-Flash`，并在威胁有效性里声明「只有一个模型族」 | `results/main/run_manifest.json` 记录模型 ID、日期、温度、max_tokens、并发 |

另外三点变化：

- **不再有 `always_observe` 护盾**：旧 pilot 有一个「每次抓取前强制 observe 一次」的策略盾，
  它本身就是一条环境专用策略，pilot-v1 的 `always_observe` 因此不是一个干净的对照。本实验没有护盾。
- **环境版本由脚本参考线选定，不由 LLM 结果挑**：新环境在 1000 个种子（0–999）上逐格复现旧环境
  `fixed+askcap1` 变体的 24 格参考表（success 差 ≤0.1pp、cost 差 ≤0.1），环境是「先定后跑」。
- **旧仓库只读**（`_ref/`，已 `.gitignore`），本仓库从零实现，没有复制旧的大而全结构。

## 3. 方法与一致性检查

### 3.1 环境（只改两处）

| 改动 | 内容 |
|---|---|
| (a) 整词匹配 | `ask_human` 用 `named_items(question)`：`notebook` 不再命中 `book`；`coffee mug` 与 `coffee_mug` 都认 |
| (b) `max_asks` | 主版本 1：第 2 次**有效**问人起返回 `INVALID: ask limit reached.`（0 预算、占 1 步）；无效提问不计入次数 |

未改动：5 房间、18 件物品（6 件 high_risk）、预算 60、最长 30 步、成本
move 2 / observe 3 / ask_human 10 / pick 1 / place 1、缺失 pick −15、high_risk 误抓或抓空
−25 且立即失败、`inspection_gap=8`、p∈{0,0.2,0.4}、`n_targets = 2 + seed % 2`、
室友优先移动当前待办目标、被问过的物品在抓住前不再被移动。

**环境版本由脚本参考线选定，不按 LLM 结果调整。** 在 1000 个种子（0–999）上，新环境逐格复现旧环境
`fixed+askcap1` 变体的参考线（容差 success ±2pp、cost ±1.5，实测差 ≤0.1）：

| policy | p=0 | p=0.2 | p=0.4 |
|---|---|---|---|
| trust_memory | 100 / 11.8 | 46.5 / 26.6 | 26.2 / 30.7 |
| observe_pick | 100 / 19.3 | 64.5 / 41.9 | 36.8 / 47.8 |
| ask_fetch | 100 / 26.3 | 66.3 / 43.4 | 46.3 / 47.4 |
| ledger_gate | 100 / 11.8 | 70.9 / 42.7 | 47.6 / 47.6 |

主版本里没有任何脚本策略一招通吃（p=0.2 最高 70.9%，p=0.4 最高 47.6%），环境因此具备分辨力。
对照：旧环境原样里 `ask_fetch` = 100 / 96.1 / 94.2 —— 这正是旧闸门不可信的主因。

### 3.2 两个正交开关

| | P=N（neutral） | P=C（cost-aware） |
|---|---|---|
| **R=window** | `win_N` | `win_C` |
| **R=append** | `app_N` | `app_C` |
| **R=ledger** | `led_N` | `led_C` |

一致性铁律：**除 R、P 之外，臂与臂之间一个字符都不许不同。**

- `BASE_SYSTEM` 六个臂逐字相同（2,502 字符）。它以旧 pilot 的 `BASE_SYSTEM` 为起点，补上了旧版只告诉
  部分臂的规则：被问过的物品在抓住前不再被移动、每局最多问人 1 次、18 个物品的风险级别、
  `disturbance_p` 的含义；并把旧版那个非法示例 `Where is the current_target item?` 换成合法的
  `Where is the coffee_mug?`（旧版安全规则的一句话也改成了与实现一致的写法）。
- `P=C` 在 BASE 末尾逐字追加固定的 DECISION GUIDANCE 段（441 字符 → 系统提示 2,944 字符），
  不加任何环境专用微策略。
- 用户消息 = `{"state", "recent_history", "memory"}`：`state` 与 `recent_history` 六个臂逐字相同，
  只有 `memory` 字段随 R 变化。`memory` 全部由代码确定性构造，不用 LLM 抽取。

这些不变量由 `tests/test_prompts.py` 强制：系统提示只在 P 后缀处不同、用户消息只在 `memory` 字段不同，
并且是**整局**逐步对比（同一 stub 客户端跑六臂，逐请求比对）。每臂 prompt 的字符数见
[`docs/PARITY.md`](../docs/PARITY.md)。

### 3.3 记忆构造与信息等价

- `window`：`[]`（无长期记忆，也看不到巡检记录）。
- `append`：只追加的原始记录 —— 巡检 5 条（step=−8）、每次 observe 一条、每次有效 ask_human 一条、
  每次失败的 pick 一条；不加任何评论性文字。
- `ledger`：每个物品一行 `{"item", "believed_room", "last_verified_step", "age", "source",
  "superseded_count"}`，`believed_room` 为 null 时额外带 `last_room`；更新规则照旧仓库的
  `ledger.py`（正向看到 → 覆盖并累计 superseded；观察到缺失 → 置 null；失败 pick → 置 null）。
  `risk_level` 不进 ledger（已在 BASE 里）。

信息等价由 `tests/test_memory.py` 保证：200 条随机事件序列下，ledger 的每个字段都能**只由 append 日志**
重算（ledger 的信息不多于 append）；ledger 里存的是「信念」而不是真值——测试断言目标物被室友移动后，
ledger 仍记着巡检时的房间。

### 3.4 运行与统计

- 模型 `minimax-code-global/MiniMax-M3.1-Flash`（本地 Magpie 网关，OpenAI 兼容协议），
  temperature=0、max_tokens=4000、单请求硬墙钟 150s。网关探测见 [`docs/GATEWAY.md`](../docs/GATEWAY.md)：
  5 轮并发扫描（1/4/8/10/12），选中并发 10（各轮中位吞吐最高且长尾最短）。
- 每步 1 次 LLM 调用；解析失败**重发同一请求**最多 2 次（不占步数，记 `format_retries`），
  仍失败则当一次 INVALID 动作（占 1 步、不扣预算）。基础设施失败（超时/空响应/5xx/限流）
  用指数退避重试到拿到有效回复，不算 agent 失败；重试仍失败的回合标 `infra_failed`，不进分析，
  最后补跑。
- 每局写盘才算完成，可断点续跑；`prompts.lock` 冻结提示模板与记忆构造代码的哈希，不一致时拒绝运行。
- 统计：所有对比按种子配对；95% CI = 对种子的配对 bootstrap（10,000 次，固定随机种子 20261117，
  同一种子的所有 p 与臂一起重抽）；δ = 10pp。

### 4.2 判定量与决策表

| 判定量 | 效应 (pp) | 95% CI | 判定 |
|---|---|---|---|
| **S**（记忆结构，p∈{0.2,0.4}） | +2.3 | [−3.2, +7.5] | **STRUCTURE_NOT_NEEDED** |
| **S0**（阴性对照，p=0） | +0.5 | [+0.0, +1.5] | control OK（CI 下界恰为 +0.0，0 在区间内） |
| **S_DiD** = S − S0 | +1.8 | [−3.8, +7.2] | STRUCTURE_NOT_NEEDED |
| **Π**（策略提示，p∈{0.2,0.4}） | +1.8 | [−4.0, +7.5] | **PROMPT_NOT_NEEDED** |

主实验（N=60）时 S = +0.0 [−7.1, +6.7] → STRUCTURE_NOT_NEEDED、Π = +2.5 [−5.4, +10.4] →
PROMPT_INCONCLUSIVE，触发了预注册里唯一一次 N=100 延伸（种子 1060–1099）。
延伸后 Π 的 CI 上界降到 +7.5（< δ=10），从 INCONCLUSIVE 变成 **PROMPT_NOT_NEEDED**。

**决策表结论**（`PREREG.md` §7 原样）：

| S | Π | 论文叙事 |
|---|---|---|
| STRUCTURE_HELPS | 任意 | 同提示下结构仍然有效 → 继续这条线,补第二个模型/环境变体 |
| STRUCTURE_NOT_NEEDED | PROMPT_HELPS | 提升来自成本感知提示而不是记忆结构 → 转成"何时信记忆、何时重新观察、何时问人"的成本感知策略研究 |
| **STRUCTURE_NOT_NEEDED** | **PROMPT_NOT_NEEDED** | **负结果:过期记忆的伤害是真的,但结构与轻量提示都没解决 → 受控实证 + 失败分类** ← 本次落入这一行 |

注意「NOT_NEEDED」的含义是**效应确知小于 10pp**，不是「效应恰为 0」：S 的 CI 是 [−3.2, +7.5]、
Π 的 CI 是 [−4.0, +7.5]，数据与「效应在 ±8pp 以内」相容。

### 4.3 p=0 的「过度核验」代价（单独报告）

| 对比 | SR 差 (pp) | cost 差 |
|---|---|---|
| app_C − app_N | +1.0 | +0.7 |
| led_C − led_N | +0.0 | −1.3 |

世界静止时，成本感知提示既没有提高也没有降低成功率，成本变化在 ±1.3 点以内 —— **「过度核验」在这个
环境里几乎不花钱**。

| 对比 | p=0 | p=0.2 | p=0.4 |
|---|---|---|---|
| app_N − win_N | **+49.0** [+39.0, +59.0] | +1.0 [−12.0, +14.0] | +8.0 [−4.0, +20.0] |
| led_N − win_N | **+50.0** [+40.0, +60.0] | +2.0 [−12.0, +16.0] | +3.0 [−8.0, +14.0] |
| app_C − win_C | **+49.0** [+39.0, +59.0] | +4.0 [−8.0, +16.0] | +1.0 [−10.0, +12.0] |
| led_C − win_C | **+49.0** [+39.0, +59.0] | **+14.0** [+2.0, +27.0] | +4.0 [−8.0, +16.0] |

### 4.5 失败机制（696 个失败局）

| 类别 | 失败局 | app_N | led_N | app_C | led_C | win_N | win_C |
|---|---|---|---|---|---|---|---|
| 问人浪费（用掉唯一一次问人后又问一次） | 313 | 46 | 34 | 49 | 46 | 65 | 73 |
| 核验后目标又被移走 | 204 | 29 | 45 | 32 | 29 | 37 | 32 |
| 信了过期记忆 | 178 | 22 | 21 | 19 | 13 | 53 | 50 |
| 格式无效 | 1 | 0 | 0 | 1 | 0 | 0 | 0 |

重叠签名：**93.7%** 的失败局在用掉唯一一次问人后又问了一次；**77.3%** 因此耗尽预算；
**54.9%** 有过抓空；**24.7%** 以安全违规收场。

「信了过期记忆」这一类在 window 臂上最重（53 / 50 局）：它们其实不是「信了会过期的信念」，
而是**手里根本没有关于位置的证据时仍然去抓**（例如第 26 步在一个从未观察过的房间里抓一个 24 步前问过
的物品）—— 问人答案早就滑出了 4 步的 `recent_history` 窗口。

### 4.6 取证年龄：为什么不是「记忆结构」的问题

每次抓取时，该物品最近一次被证实位置距今多少步 → 抓空率（N=100，全部臂）：

| 最后证据的来源 | p=0 | p=0.2 | p=0.4 |
|---|---|---|---|
| **观察**（observe） | 1.4% (10/729) | **17.6%** (138/783) | **31.3%** (243/777) |
| **人的答案**（ask_human） | **0.0%** (0/253) | **0.0%** (0/548) | **0.0%** (0/541) |
| 没有任何证据（盲抓） | 10.9% (49/449) | 78.5% (62/79) | 87.5% (49/56) |

**人的答案一次都没有失手（1342 次抓取，0 次落空）**，因为环境规定「被问过的物品在抓住前不再被移动」；
而哪怕是上一步刚观察到的证据，在 p=0.4 也有 **31.3%** 的抓空率 —— 室友在观察和抓取之间就把物品搬走了。
按证据年龄分档（p=0.4）：≤1 步 25.9%、2–7 步 1.8%、≥8 步 81.6%。

这解释了整张主表：**每局有 2–3 个目标，但只有 1 次问人机会**（`max_asks=1`），
所以多数目标只能靠「观察 → 抓」，而这条路的抓空率随 p 迅速恶化。记忆结构与提示都改不了这个
**资源约束**：换更好的记忆表示不会让一次观察更可靠，换更聪明的提示也不会凭空多出一次问人。
图：[`results/figures/evidence_age.png`](figures/evidence_age.png)、[`evidence_age_by_arm.png`](figures/evidence_age_by_arm.png)。

### 4.7 相对脚本参考线的位置（Pareto）

同样的 100 个种子上的脚本参考线（success% / cost）：

| policy | p=0 | p=0.2 | p=0.4 |
|---|---|---|---|
| trust_memory | 100 / 11.5 | 41.0 / 28.3 | 33.0 / 32.5 |
| observe_pick | 100 / 19.0 | 61.0 / 42.4 | 38.0 / 46.7 |
| ask_fetch | 100 / 26.0 | 60.0 / 43.9 | 44.0 / 45.7 |
| ledger_gate | 100 / 11.5 | 64.0 / 43.3 | 39.0 / 48.8 |

- p=0：脚本全 100%；LLL 记忆臂 99–100%，window 臂 50–51%。
- p=0.2：最好 LLM 臂 `led_C` 67.0% vs 最好脚本 `ledger_gate` 64.0%。
- p=0.4：最好 LLM 臂 `app_N` 48.0% vs 最好脚本 `ask_fetch` 44.0%。

**LLM 臂与 20 行脚本基本打平**，而且在 p=0 时脚本完胜（成本 11.5–26.0 vs LLM 16.7–21.9）。
图：[`results/figures/pareto.png`](figures/pareto.png)。

**成本占优**（SR 差不低于 −2pp 且 cost 配对差 CI 上界 < 0）：p=0.2 时 `app_N`（cost −4.5 [−7.9, −1.2]）、
`app_C`（−3.7 [−7.0, −0.4]）、`led_C`（−3.6 [−6.9, −0.2]）相对 `win_C` 记为成本占优；
其余组合均不满足（完整表见 [`cost_dominance.md`](tables/cost_dominance.md)）。

### 4.8 一句话总结

在这个环境里，**记忆「表示」和「策略提示」都不是瓶颈**：把 append 日志压缩成带年龄和 superseded 计数的
ledger 不比原始日志更好，加一段 441 字符的成本感知提示也不比没有更好，两者都确知小于预注册的 10pp 门槛。
真正决定成败的是**证据的寿命**（一步就会过期）和**每局只能问一次人**这个资源约束 ——
而这两者都不是记忆设计问题。

## 5. 威胁有效性

1. **只有一个模型族**（MiniMax-M3.1-Flash），不能外推到其他模型的能力结构；
   本实验也不复现 pilot-v1 的双模型设计（DeepSeek 额度已耗尽）。
2. **文本玩具世界**：5 房间 18 物品、规则完全已知、决策空间只有 5 种动作。
   与真实家居环境（部分可观测、连续物理、多目标）的差距没有估计。
3. **记忆由代码确定性构造**（无抽取噪声）：因此本实验不测「LLM 自己抽取记忆时出错」
   这一类失败来源；这是有意简化，好让 R 的效应可以归因到表示形式本身。
4. **室友偏向目标**：随机从 18 件物品里移动只有约 10% 命中目标，「过期」几乎不会发生，
   所以保留「优先移动当前待办目标」这条规则。它让场景更容易制造过期记忆，但也让
   环境偏向「当前目标」，这是已知的设计选择。
5. **P=C 是轻量的原则性提示**（441 字符的一段决策指导），不代表重度工程化的提示
   （不是 few-shot、不是 CoT、不是工具增强、不是自我反思）。因此「提示无效」这个结论
   只针对**轻量**提示。
6. **环境版本由脚本参考线选定**（不是由 LLM 结果挑的）：新环境在 1000 个种子上逐格复现
   旧环境的脚本参考线，主版本里没有任何脚本策略一招通吃（p=0.2 最高 70.9%、p=0.4 最高 47.6%）。
7. **BASE_SYSTEM 里已经含有一句 `Be economical but do not risk stale high_risk picks`**
   （沿用旧版，六个臂都有）——它略微削弱了 P=C 的相对优势，这一点在此如实说明。
8. **单一研究者、无重复实验**：bootstrap CI 只覆盖种子抽样带来的不确定性，
   不覆盖「换一批种子 / 换一种提示写法 / 换一种模型」的不确定性。
9. **问人上限对 agent 不可见**：公共状态里没有「还能问几次」，agent 只能从最近 4 步的
   `recent_history` 里推断自己问过没有。这不是实验设计的选择，而是规格里
   「每局最多问人 1 次」与「公共状态字段同旧 state_context」两条并存的必然结果，
   旧环境里没有这个上限所以没有暴露。它对六个臂对称，因此不污染 S/Π 的比较，
   但它系统性地压低了所有 LLM 臂的水平（见失败分类）。
10. **N=100 的延伸只回答同一个问题**：它按预注册的唯一规则触发，用更大的样本重判 S 与 Π；
    它不能替代第二个模型或第二个环境。
11. **成本占优的判定是描述性的**：三个组合满足「成本占优」，但这不改变 S/Π 的判定
    （按预注册的规定）。

## 6. 下一步

1. **补第二个模型族**（如 DeepSeek 额度恢复后，或本地 Ollama 上的开源模型）：
   「结构与提示都无效」目前只在 MiniMax-M3.1-Flash 上成立；`led_C` 在 p=0.2 上是唯一
   显著优于 window 臂的组合（+14.0pp [+2.0, +27.0]），值得看它是否模型相关。
2. **把 `max_asks` 变成可观测的**（在公共状态里给出剩余问次数），或者让 `recent_history`
   更长：这样「问人浪费」（93.7% 的失败局）这条失败链就被切断，可以重新检验
   「结构 / 提示是否有用」。这是一个**环境语义**改动，按规则必须先问过使用者。
3. **跑 `nofreeze` 稳健性变体**（不冻结被问过的物品、不限问人次数，4 个核心臂 × 3 个 p ×
   种子 1000–1039）：它把「人的答案永远可靠」这条最强的机制拿掉，可以检验
   4.6 节那条结论是不是只是冻结规则的产物。规格把它列为可选、在主结论之后跑。
4. **把「证据寿命」本身作为自变量**：在 p=0.2 / 0.4 上测量「观察→抓」的空窗步数
   （0 / 1 / 2 步）对抓空率的影响，给出「多久必须重新定位一次」的定量规律，
   这比比较两种记忆表示更接近可用结论。
5. **论文叙事**：按决策表第三行走「受控实证 + 失败分类」：pilot-v1 的「结构有效」是臂混杂的产物，
   修好对照后效应确知小于 10pp；真正的失败机制是证据寿命与问人配额。
